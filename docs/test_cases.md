# 清穹 App 语音与故障模块测试用例

## 1. 测试环境说明

本轮测试基于 `voice_commands.md`、`warning_rules.md` 和模拟状态数据进行，不连接真实机器人，不验证真实传感器、网络、定位模块或底盘动作，也不测试精美 UI、动画、视觉还原度和不同屏幕尺寸下的布局效果。

测试重点包括：

- 中文语音到标准命令的识别结果。
- `A区`、`B区`、`C区` 的区域提取结果。
- 多命令和多故障场景下的优先级。
- 故障编号、提示文案、严重程度和 App 控制限制。
- 重复消息去重、无效语音隔离等安全规则。

当前所有“测试结果”默认填写为“待执行”。后续使用模拟数据执行测试时，应改为“通过”或“失败”，失败项必须关联 Bug 记录。

语音测试公共断言：

- 有效语音的 `recognized` 应为 `true`，并且最多输出一个标准命令。
- 无效语音的 `recognized` 必须为 `false`，不得调用 `RobotController`，不得改变机器人状态；提示文案按普通无效、非明确指令、不支持区域或多区域冲突分别断言。
- 表格中的区域 `-` 表示未指定区域；命令 `-` 表示不生成标准命令。
- 多种无效条件并存时，按“空输入 → 非明确语句 → 不支持区域 → 多区域 → 命令匹配”的顺序断言结果。
- 每条 demo 用例还必须断言 `originalText` 等于原始输入，并断言 `shouldExecute` 与是否应执行一致。
- demo 必须直接断言 `commandPriority` 为 `emergencyStop > reset > stop > pause > resume > charge > start`。
