# 清穹 App 语音命令规则

## 1. 文档目的

本文档定义清穹无人清扫车 App 的中文语音命令识别、安全拦截、区域提取和结果提示规则。语音解析器只返回识别结果，不直接修改机器人状态；实际控制必须由统一的 `RobotController` 判断并执行。

## 2. 标准识别结果与提示

语音解析结果至少包含：

| 字段 | 含义 |
| --- | --- |
| `recognized` | 是否识别到明确且有效的控制指令 |
| `command` | 标准命令；无效时为 `null` |
| `area` | 标准区域；未指定时为 `null` |
| `originalText` | 原始输入文本 |
| `message` | 本次识别的统一提示 |

提示文案必须统一为：

| 场景 | 标准提示 |
| --- | --- |
| 有效命令 | `已识别指令：<command>` |
| 普通无效语句 | `未识别到有效控制指令` |
| 否定句、询问句或说明句 | `该语句不是明确的控制指令` |
| 出现不支持区域 | `不支持的清扫区域` |
| 同时出现多个不同区域 | `一次只能指定一个清扫区域` |

## 3. 安全拦截规则

命令匹配前必须先执行安全拦截。只接受明确要求机器人执行操作的控制指令，不得仅因为句子中出现命令关键词就执行控制。

统一判定顺序为：

1. 空字符串或纯空格：返回普通无效提示。
2. 否定句、询问句或说明句：返回“该语句不是明确的控制指令”。
3. 出现不支持区域：返回“不支持的清扫区域”。
4. 同时出现多个不同的受支持区域：返回“一次只能指定一个清扫区域”。
5. 检查连接词前后是否都有完整控制子句；不完整或连续连接词返回“该语句不是明确的控制指令”。
6. 完成以上检查后，才按有序命令规则表匹配控制指令。

同一句同时符合多个无效条件时，以以上顺序最先命中的结果为准。

### 3.1 否定句必须拒绝

以下表达均为无效语音：

- 不要开始清扫
- 别暂停任务
- 不要复位
- 不用返回充电
- 禁止继续任务
- 无需停止任务
- 不能继续任务
- 不要开始清扫D区（安全拦截优先于区域错误）

否定句必须返回 `recognized=false`、`command=null`，提示“该语句不是明确的控制指令”，不得调用控制器。

### 3.2 询问句和说明句必须拒绝

以下表达均为无效语音：

- 可以开始清扫吗
- 如何返回充电
- 复位按钮在哪里
- 紧急停止是什么意思
- 怎么暂停任务
- 能否开始清扫
- 如何复位
- 可以复位吗

询问句和说明句必须返回 `recognized=false`、`command=null`，提示“该语句不是明确的控制指令”，不得执行控制。

### 3.3 明确控制指令

以下形式属于明确控制指令：

- 请开始清扫
- 开始清扫A区
- 暂停任务
- 继续清扫
- 停止任务
- 返回充电
- 紧急停止
- 解除急停

“请”“帮我”“麻烦”等礼貌前缀可以忽略，但移除礼貌前缀后，剩余内容必须完整匹配受支持的控制表达。

### 3.4 连接词完整性

使用“后”“之后”“然后”“并”“并且”等连接词组合多个命令时，连接词前后都必须存在完整控制子句。

以下表达均为无效语音：

- 开始清扫后
- 停止任务并
- 后执行复位
- 并开始清扫
- 开始清扫然后
- 开始清扫并然后停止任务

只要连接词位于句首、句尾，或连续连接词之间没有完整子句，整条语音必须返回 `recognized=false`、`command=null`、`shouldExecute=false`，提示“该语句不是明确的控制指令”。不得过滤空子句后继续匹配。

## 4. 标准命令与受支持表达

标准命令只能使用以下 7 个名称：

| 标准命令 | 含义 | 受支持的明确表达 |
| --- | --- | --- |
| `start` | 开始清扫 | 开始清扫、开始任务、启动清扫、执行清扫任务、开始工作、去清扫、清扫A区、清扫B区、清扫C区、执行A区清扫、执行B区清扫、执行C区清扫 |
| `pause` | 暂停任务 | 暂停一下、暂停任务、暂停清扫、先停一下、任务暂停、暂停某个受支持区域的清扫任务 |
| `resume` | 继续任务 | 继续清扫、继续任务、恢复清扫、恢复任务、接着清扫、继续工作，可指定一个受支持区域 |
| `stop` | 普通停止任务 | 停止任务、停止清扫、结束清扫、终止任务、结束任务、结束某个受支持区域清扫 |
| `charge` | 返回充电 | 返回充电桩、回去充电、开始充电、返回充电、去充电、回充、回充电桩 |
| `emergencyStop` | 紧急停止 | 紧急停止、立即停止、立即停止任务、马上急停、启动急停、紧急制动、危险快停下、马上停下 |
| `reset` | 解除急停并复位 | 解除急停、解除紧急状态、执行复位、确认复位 |

### 4.1 复位命令安全规则

`reset` 只接受以下明确表达：

- 解除急停
- 解除紧急状态
- 执行复位
- 确认复位

单独输入“复位”不得识别为 `reset`。“不要复位”“复位按钮在哪里”“如何复位”“可以复位吗”也必须拒绝。

解析器只返回 `reset` 请求。当前是否处于紧急状态、是否允许复位以及复位后的机器人状态，必须由 `RobotController` 判断。

## 5. 清扫区域提取规则

只支持以下三个标准区域：

| 标准区域 | 可接受写法 |
| --- | --- |
| `A区` | A区、A 区、a区、a 区 |
| `B区` | B区、B 区、b区、b 区 |
| `C区` | C区、C 区、c区、c 区 |

区域规则如下：

1. 区域字母忽略大小写及字母与“区”之间的空格。
2. 一条有效命令未提到区域时，`area=null`。
3. 只输入一个受支持区域而没有命令时，保留提取结果，例如输入“A区”返回 `area=A区`，但同时返回 `recognized=false`、`command=null`，不得执行控制。
4. 只要语句中出现 A/B/C 之外的区域表达，整条语音无效，并提示“不支持的清扫区域”。
5. 不支持区域包括但不限于：1区、甲区、东区、D区、教学楼一区。
6. 同一句出现多个不同区域，例如“A区和B区”或“B区和C区”，整条语音无效，并提示“一次只能指定一个清扫区域”。
7. 同一个受支持区域重复出现不构成区域冲突，但命令本身仍必须是明确控制指令。
8. 普通词语中的“区”不等于清扫区域。“小区”“区域”“清扫区域”“当前区域”不得返回“不支持的清扫区域”；如果整句没有有效控制命令，应按普通无效语音处理。

## 6. 命令识别优先级

命令识别必须使用一张有序规则表，同时作为匹配顺序和公开的 `commandPriority`，不得维护两套独立顺序。

优先级固定为：

1. `emergencyStop`
2. `reset`
3. `stop`
4. `pause`
5. `resume`
6. `charge`
7. `start`

一条语音包含多个明确命令时，只返回优先级最高的一个命令。例如：

- “立即停止任务”返回 `emergencyStop`，不能返回 `stop`。
- “紧急停止后返回充电”返回 `emergencyStop`。
- “解除急停后开始清扫”返回 `reset`。
- “停止任务，暂停一下，然后继续清扫”返回 `stop`。

## 7. 普通停止与紧急停止

### 7.1 普通停止 `stop`

`stop` 用于正常结束任务，例如“停止任务”“结束清扫”。普通停止不代表危险或急停状态。

### 7.2 紧急停止 `emergencyStop`

`emergencyStop` 用于要求机器人立即停止的安全场景，例如“紧急停止”“立即停止”“立即停止任务”。它的优先级最高。

### 7.3 冲突规则

- 明确的“立即停止”或“紧急停止”表达必须识别为 `emergencyStop`。
- 正常结束表达“停止任务”“结束清扫”识别为 `stop`。
- 同一句同时包含两类明确命令时，只返回 `emergencyStop`。
- 否定或询问表达先被安全拦截，不进入普通停止或紧急停止匹配。

## 9. 安全规则

1. 否定句、询问句、说明句和无关语音不得执行命令。
2. 识别失败时只返回提示，不执行默认操作，不沿用上一条命令。
3. 区域不支持或多个区域冲突时，不得执行任何控制。
4. 普通词语中的“区”不得误判为清扫区域。
5. 连接词前后必须存在完整控制子句，任何空子句都不得执行命令。
6. 一条有效语音最多返回一个标准命令，多命令按固定优先级处理。
7. `emergencyStop` 优先级最高，`reset` 只能由明确复位表达触发。
8. 解析器不得自行修改、模拟或绕过控制器修改机器人状态。
9. 所有实际机器人控制必须统一交给 `RobotController` 校验和执行。

本文档只定义纯 Dart 语音解析规则，不包含 Flutter、第三方插件或真实机器人控制实现。
